## 1. Identity of the extension

### `ConformanceLevel`

Conformance level that a seller declares.

- 1 Inform: `get_distributor`, `list_products`
- 2 Quote: level 1, plus `quote`
- 3 Subscribe: level 2, plus `submit_application` and `get_operation`

A server that declares a level MUST implement every tool of that level and of the levels below it.

Type: one of `1`, `2`, `3`.

### `AipSettings`

Settings object of the extension. A server puts it under `capabilities.extensions["org.agenticinsuranceprotocol/aip"]` in its MCP `server/discover` response, and in its [`AipDocument`](#aipdocument).

| Field | Type | Required | Description |
|---|---|---|---|
| `version` | string | Yes | Protocol version the server implements, "major.minor", for example "0.1". Until 1.0, a client MUST treat a different minor version as a different protocol. |
| `conformance_level` | [`ConformanceLevel`](#conformancelevel) | Yes |  |
| `lines` | list of [`ProductLine`](#productline) | Yes | Product lines the server can quote. |
| `countries` | list of [`CountryCode`](#countrycode) | Yes | Countries where the server's products are sold. |

### `AipDocument`

The AIP document of a seller, at `https://{domain}/.well-known/aip.json`. It leads from a domain to its MCP server. The seller MUST serve it from that host, with no redirect to another host, so that the document proves that the seller controls the domain.

## 2. Common types

### `CountryCode`

ISO 3166-1 alpha-2 country code, upper case.

Type: string. Pattern: `^[A-Z]{2}$`.

### `SubdivisionCode`

ISO 3166-2 subdivision code, upper case, for example "US-CA" for California.

Type: string. Pattern: `^[A-Z]{2}-[A-Z0-9]{1,3}$`.

### `CurrencyCode`

ISO 4217 currency code.

Type: string. Pattern: `^[A-Z]{3}$`.

### `Lei`

Legal Entity Identifier (ISO 17442): 18 letters or digits, then 2 check digits.

Type: string. Pattern: `^[A-Z0-9]{18}[0-9]{2}$`.

### `LanguageTag`

BCP 47 language tag, for example `fr` or `en-GB`.

Type: string. Pattern: `^[a-zA-Z]{2,3}(-[a-zA-Z0-9]{2,8})*$`.

### `DateString`

Calendar date, ISO 8601.

Type: string (date).

### `DateTimeString`

Date and time with offset, ISO 8601.

Type: string (date-time).

### `Url`

Type: string (uri).

### `Decimal`

A decimal number as a string, so that no value is lost to floating point, for example "12.90".

Type: string. Pattern: `^-?[0-9]+(\.[0-9]+)?$`.

### `ProductLine`

Product line. Servers SHOULD use a value of [`KnownProductLine`](#knownproductline). Other values MUST be lower case with underscores.

Type: string. Pattern: `^[a-z][a-z0-9_]*$`.

### `KnownProductLine`

Common product lines.

### `KnownInsuredFamily`

## 5. Quote (level 2)

### `AnswerSources`

The source of each answer, keyed like `answers`. An agent MUST give a source for each answer, and no source for a key that has no answer. Otherwise the server returns `answers_invalid`.

Type: map of [`AnswerSource`](#answersource).

### `QuoteParams`

Params of `quote`.

The agent sends the answers that it has, even none. When answers are missing, the server returns `needs_input` with the questions of the product and the missing fields. The agent asks the customer, and calls `quote` again with all the answers. This one loop replaces the tools that give the questions, and the multi-step flow tools (`action`, `stateUpdates`, `sessionId`) that most servers use.

The server keeps the answers and their sources with each offer, until its `valid_until`. `submit_application` takes them from the offer, so the agent does not send them again.

| Field | Type | Required | Description |
|---|---|---|---|
| `product_id` | string | Yes |  |
| `answers` | [`Answers`](#answers) | Yes | The answers that the agent has. Empty in a first call that has none. |
| `answer_sources` | [`AnswerSources`](#answersources) | Yes | Where each answer comes from, keyed like `answers`. |
| `options` | list of string |  | Options the customer wants priced, by key (optional covers, extra services). |
| `language` | [`LanguageTag`](#languagetag) |  |  |

When a server implements `quote`, an agent MUST take the price, the cover, the limits and the excess that it shows the customer from the offer, and MUST NOT take them from a page made for people.

When the customer wants to change an answer, the agent calls `quote` again, and applies for an offer of the new quote.

| Field | Type | Required | Description |
|---|---|---|---|
| `offer_id` | string | Yes |  |
| `parties` | list of [`Party`](#party) | Yes |  |
| `language` | [`LanguageTag`](#languagetag) |  | Language of the `summary` and of the approval page. |

### `SubmitApplicationResult`

An application that waits for the customer. `submit_application` commits nothing. The customer approves the application on the seller's page at `url`, then signs and pays on the same site. When the client declares MCP URL-mode elicitation, the server SHOULD open the page with a URL-mode elicitation of `url`. Otherwise the agent gives the customer `url`.

The seller MUST keep what the customer approved, with the answers and their sources, the price and the documents, for the period that the law requires.

| Field | Type | Required | Description |
|---|---|---|---|
| `application_id` | string | Yes |  |
| `application_key` | [`ApplicationKey`](#applicationkey) | Yes | The key to read the application with `get_operation`. See [`ApplicationKey`](#applicationkey). |
| `summary` | string | Yes | The application in plain words, so that the customer can decide from it alone: the product, the tier, the insurer and the price. It MUST give each answer and its source, and MUST ask the customer to approve only when each answer is true and complete, so that the approval is also the customer's confirmation of the answers. |
| `url` | [`Url`](#url) | Yes | The seller's page where the customer approves the application, then signs and pays. Before the customer can approve, the page MUST show the firm price, each answer with its source, and a link to each document of the product and of the offer with `required_before_commitment: true`. It MUST let the customer approve or refuse. The page MUST take an approval only from a form that the person submits on it, never from a GET request, so that a link preview cannot approve. The URL MUST be on the domain of the seller, MUST hold a token of at least 128 bits of randomness that is neither the `application_id` nor the `application_key`, and MUST NOT contain personal data. |
| `expires_at` | [`DateTimeString`](#datetimestring) | Yes | Last moment the customer can approve. After it, the application is `expired`. |

### `ApplicationKey`

The key to read an application with `get_operation`. The server returns it only in the result of `submit_application`. It MUST hold at least 128 bits of randomness. It is not in the approval page, so the agent keeps it to itself.

Type: string.
