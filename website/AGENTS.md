# The AIP website

The rules of the root `AGENTS.md` apply here too. Paths in this file start from `website/`, except the paths that start with `spec/` or `skills/`, which start from the root of the repository.

## Site

The site is a Next.js app in `app/`, `components/` and `lib/`, and the build prerenders every page except `/login`. It is a workspace of the root package: `bun install` at the root installs it, and `bun run dev` and `bun run build` at the root run it from `website/`. The build reads `spec/` and `skills/` from the root, so `next.config.ts` sets the root of the build to the folder above, and `REPO_ROOT` in `lib/repo-files.ts` finds the root for each read. On Vercel, the Root Directory of the project is `website`. Until the launch, the site is private. `proxy.ts` sends each request without the access cookie to `/login`, and the login page sets the cookie when the password is correct (`lib/access.ts`). Only the files that the login page loads and the paths for an AI agent stay open: `/llms.txt`, `/install.md`, which `vercel.json` redirects to the install steps in the docs, and `/schemas/` and `/skills/`, which the docs link to. The password is the `SITE_PASSWORD` environment variable on Vercel, and production gives a 503 without it. A new password logs everyone out. To open the site, delete `proxy.ts`, `app/login/` and `lib/access.ts`. The `/join` page holds the form of the launch partners (`components/partner-form.tsx`), and both "Become a launch partner" buttons of the home page open it. The form saves each request through the server action in `lib/partner-request.ts`, in the `partner_requests` table of the Neon database in the `DATABASE_URL` environment variable. Locally, that variable is in `website/.env`. The `/submit` page holds the form where a seller asks to be listed in the registry (`components/listing-form.tsx`), and no menu or button of the site links to it yet. The form has three steps. The first runs steps 2, 3 and 5 of the listing in the registry spec (`lib/server-check.ts`): it reads the `aip.json` of the domain, calls the MCP server, and checks the tools of the level. It reads each address through `lib/safe-fetch.ts`, which applies the network rules of section 2.1. The second shows the licences that `get_distributor` declares, and the third takes the contact details. `lib/listing-request.ts` runs the checks again, and saves the request in the `listing_requests` table. The operator checks each licence by hand. Drizzle defines the tables in `db/schema.ts`. After a change there, run `bun run db:generate`, commit the migration that it writes in `db/migrations/`, and apply it with `bun run db:migrate`. Don't edit `db/migrations/` by hand. The docs are not part of the site. Mintlify serves them from `docs/` at docs.agenticinsuranceprotocol.org, as the section "Docs" of the root `AGENTS.md` says. `lib/site.ts` holds their addresses, and the site links to them with `<a>`, not with `Link`. `/llms.txt` sends an AI agent to the docs, and lists the files that only the site serves. Preview with `bun run dev`, and run `bun run build` before a pull request.

The section "From discovery to the contract" of the home page shows three sales, one in each country, in the stepper of `components/home/sale-stepper.tsx`. Each step has the chat, with a short line for each call of a tool where the AI agent makes it. Beside it are the text of the step, the details of its calls (route and result) behind "Show the calls", the owner and the proof. The first sale is the sale of the explainer video, on the steps of the skill: the step titles come from `guidelines.md`, and `SALE` in `app/page.tsx` gives each one its content. The build fails when a step of the skill has no entry in `SALE`. The third sale reads the sellers and the licence check from `spec/examples/registry-04` and `spec/examples/registry-08`, and the build fails when that check no longer gives `not_licensed`. Write the chat in a friendly voice: the AI agent follows the rules without reciting them.

The opening picture of the home page is `components/home/explainer-video.tsx`: the explainer video, in `public/aip-explainer.mp4`. It plays only when the reader starts it. The poster, `public/aip-explainer-poster.jpg`, is a frame near the end, with every party and every proof on screen. The video is not made from this repository. When it changes, encode the new one to H.264 with `ffmpeg -c:v libx264 -preset slow -crf 28 -c:a aac -b:a 96k -movflags +faststart`. The source recording is over 30 MB, so keep it out of the repo.

## Design

Style with Tailwind utilities in the JSX. The Tailwind theme in `app/globals.css` reads every colour, gap and radius from the tokens in `app/tokens.css`, which match the AIP Design System. That file also holds the base rules and the `wrap` utility (the page width). Add no other rules there. Class lists that several files share are in `lib/ui.ts`. The breakpoints are desktop first: `max-lg:` is 980px and under, `max-sm:` is 640px and under. Write no literal colours in components. Cognac (`--accent`) appears at most in one marker per view. The site uses none today, and the docs use it as their primary colour in `docs/docs.json`. The mark is the acorn in `public/aip-mark.svg`, and `app/icon.svg` is the same file. Use the files of the design system as they are, and don't redraw or recolour the acorn. Set text in IBM Plex Sans and code in IBM Plex Mono, from `app/fonts/`. Separate with `--line` borders, not shadows.
